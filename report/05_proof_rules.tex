\subsection{Asynchronous Rules}

Our simulation decouple the stepping of the Source and of the Target.
So the rules are calls asynchronous, one stepping does nothing on the other.

Moreover, in the simulation target and source are treated differently:
- target is demonic. You need to consider all the next steps.
- source is angelic. You choose which step to look at.

\subsection{Undefined Behavior Exploitation}

Remember of the simulation.
Is the source is stuck, then the simulation trivial holds.
This thing can give us information !
Indeed, to prove that $\fsim{t}{i}{j}{s}{\Phi}$ holds,
knowing that s will execute an arithmetic op,
then 2 cases are possible:
- either this op fails. In this case EASY !:
the source is stuck, and so the simulation holds.
- either this op is successful.
And you need to prove that the simulation holds knowing that this op is successful.

So this lead to a family of exploit rules, see in fig ...

A small notes on memory rules.
in separation logic,
unless by allocation,
you can't just make appear ressouces.
So the exploit rules have a different approach:
They require the memory bijection as argument
and also a proof that the argument of the operation
are related (and so, if they are pointers, then they are in the memory bijection)

The exploit here consist on:
- Knowing that the values are indeed pointers.
- Using the meminj exploit this pair of location
- And so doing the memory operation.

So for the load, store and free,
this give the fact that the pointers could only be alive in the meminj.
After the step, if not a free, the pointer is still alive.
Because the used pair is marked as exploited now,
The user is responsible to put them back in the injection.
