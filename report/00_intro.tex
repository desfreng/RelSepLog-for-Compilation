\subsection*{General Context}

Modern software relies on high-level languages
and formal verification techniques,
such as deductive verification,
model checking,
or static analysis,
to establish correctness guarantees.
Hardware executes machine code produced by compilers,
which translate source programs through intermediate representations.
Consequently,
source-level correctness guarantees remain meaningful only if compilation
strictly preserves program semantics.
Unverified compilation passes risk introducing bugs
or invalidating source-level formal proofs.

Initial efforts in verified compilation established foundational methodologies
for proving semantic preservation.
The CompCert compiler~\parencite{leroy-09-compcert}
relies on simulation diagrams,
establishing a correspondence between execution steps
of the source and target programs
while maintaining a state invariant.
CakeML~\parencite{tan-19-cakeml},
a verified compiler for functional languages,
combines simulation diagrams with equational reasoning
to prove its correctness.
Beyond general-purpose compilers,
other verified compiler projects focus on specialized application domains.
For instance,
Jinja~\parencite{klein-06-jinja}
targets object-oriented programs compiled to the Java Virtual Machine,
whereas Jasmin~\parencite{almeida-17-jasmin}
verifies a dedicated compiler
for high-performance cryptographic software.

Existing verification paradigms exhibit limitations.
On the one hand,
equational reasoning requires programs to be sufficiently similar.
When two programs are written in different languages,
use distinct memory representations,
or follow different calling conventions,
equality may no longer be applicable
to state the soundness of the transformation.
One must instead establish
that target behaviors safely refine source behaviors.
On the other hand,
traditional simulation diagrams grow complex
because they require constructing a global invariant upfront.
This invariant must relate entire machine configurations
and whole memory states across all program points.

Recent developments in formal methods
provide techniques to address these issues.
Modern coinductive simulation frameworks,
such as the \emph{Stuttering for Free} framework by \textcite{cho-23-stuttering}
or \emph{Interaction Trees}~\parencite{xia-20-itrees},
simplify reasoning about pairs of programs
whose execution steps do not correspond one-to-one.
In parallel,
\emph{relational separation logics}
enable local reasoning across dual executions.
They allow memory resources to be tracked,
partitioned,
and treated independently between source and target heaps,
avoiding reasoning on global memory injections.
For instance,
Simuliris~\parencite{gaher-22-simuliris}
uses a relational separation logic
to verify source-to-source program transformations,
and \textcite{allain-25-tmc}
employ relational separation logic
to validate the Tail Modulo Cons optimization.

\subsection*{Research Problem}

In verified compilation,
semantic preservation is ultimately characterized by a backward simulation.
This ensures that every observable behavior of the target program
is permitted by the source program.
However,
existing compilers such as CompCert and CakeML
primarily establish forward simulations.
Forward simulations are simpler to construct,
but they only imply backward simulations
when the target language is deterministic.
Supporting target non-determinism,
such as non-deterministic assignments or concurrency,
requires establishing a backward simulation directly.

Furthermore,
existing verified compilers rely on global memory invariants
and whole-program simulation relations.
Using a relational separation logic offers a promising alternative:
it allows transformations to be verified by reasoning locally
about modified heap cells without considering the entire memory.

This internship investigates whether recent developments
in simulation relations and separation logic
can be integrated into a relational separation logic framework
and used to verify compilers.
To our knowledge,
no existing verified compiler incorporates a relational separation logic
to prove the soundness of its optimization passes.
In short,
this approach relaxes constraints present in existing systems,
such as the determinism requirements imposed by CompCert and CakeML.

\subsection*{Contributions}
\label{sec:contributions}

We developed a mechanized logic framework addressing these challenges.
At its core,
we use a coinductive safe backward simulation relation.
This frees our approach from determinism restrictions
on the source and target languages.
The simulation relation is asymmetric:
it permits target executions to exploit undefined behaviors in the source,
enabling optimizations that assume source execution does not get stuck.

Building upon this simulation relation,
we defined a relational separation logic
that enables local reasoning over fragments of source and target heaps.
The logic is parameterized by the operational semantics
of the source and target languages under comparison.
Our framework uses this logic to specify
and verify relational judgments between program components.

We instantiated this framework with a low-level imperative language,
\muRTL{},
based on the Register Transfer Language used in CompCert.
We formalized the operational semantics for this \muRTL{} dialect.
It features constructs for arithmetic operations,
dynamic heap allocation and deallocation,
and function calls.

Finally,
we established a system of relational Hoare rules for \muRTL{} programs.
This proof system comprises two distinct categories of rules.
Asynchronous rules govern unilateral execution steps taken
by either the source or the target program.
These rules enable target-side optimizations by
exploiting the absence of source undefined behavior.
Synchronous rules govern joint execution steps when both programs
advance simultaneously on matching instructions,
such as two calls to the same function.

\subsection*{Arguments Supporting Its Validity}

We evaluated our framework by verifying the correctness
of two concrete program transformations
and two general compiler optimizations.
For the concrete transformations,
the first exploits the absence of undefined behavior in the source
to eliminate a redundant zero-check after a division,
while the other hoists an invariant memory read out of a loop body.
For the general optimizations,
the first is a branch tunneling pass that eliminates redundant jumps
across arbitrary control-flow graphs.
The second,
which is omitted from the detailed exposition of this report,
optimizes redundant instructions,
such as superfluous register copies.

Beyond these case studies,
we established metatheoretic properties confirming framework soundness.
We proved that our relational separation logic soundly implies
the underlying backward simulation relation,
ensuring semantic preservation.
Additionally,
we proved that our simulation formulation,
which is easier to work with,
is equivalent
to standard backward simulation definitions used in the
literature~\parencites{leroy-09-compcert,gaher-22-simuliris,allain-25-tmc}.

The entire framework has been mechanized
in the Rocq proof assistant~\parencite{rocq}.
The development relies on the \texttt{coinduction} Rocq
library~\parencite{rocq-coinduction}
and the \texttt{stdpp} library~\parencite{rocq-stdpp}.
Furthermore,
our logic is compatible with the Iris proof mode~\parencite{krebbers-18-mosel}.

\subsection*{Future Work}

This work provides a first step for several research perspectives.
While current case studies focus on control-flow simplifications
and local rewrites,
future work will target data-flow optimizations,
ranging from constant propagation
to more complex transformations such as selective defunctionalization.

A second direction involves multi-language verification
and language independence.
Although our logic is parameterized to relate distinct languages,
our current case studies operate within a single intermediate representation.
Future work will apply the framework to translation passes
between different intermediate languages.
More generally,
we aim to keep the relational separation logic as language-independent as
possible.

Another objective is full-scale integration into CompCert.
A key question is whether our relational verification technique can be
applied incrementally,
starting with a single compilation pass
and progressively extending to other passes across the pipeline.

Finally,
we aim to support richer language features.
While our logic framework accommodates non-determinism,
our current \muRTL{} semantics features only limited non-determinism
from memory allocation.
We plan to investigate languages featuring concurrency,
structured control,
first-class closures,
or effect handlers.
In the long term,
these techniques could be applied to extend CompCert with new optimizations
and shared-memory concurrency,
paving the way toward a verified OCaml compiler.
